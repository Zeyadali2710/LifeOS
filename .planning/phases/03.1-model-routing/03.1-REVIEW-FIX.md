### CR-01: The loop's D-09 guard ignores tree and thread taint

**Files modified:** `src/server/agents/loop.ts`, `tests/db/routing-loop.test.ts`
**Commit:** a3fc33a
**Status:** fixed: requires human verification (logic change on the privacy path)
**Applied fix:** Before each free turn, if the opt-in is off, the guard now treats the run as private when any of these is true:
- `tainted` is set (the run's own `saw_private`).
- `privateInTree(h, run0.parentRunId ?? run0.id)` returns true.
- The run is a retry and `privateInTree(h, run0.retryOf)` returns true.
- The existing `mentionsSensitive` name scan matches.

The `retryOf` check is a small addition beyond the review. A retry run has no parent, so the old run's taint would otherwise be checked only at `createRun`, which is the same gap as CR-01. Every condition switches the run to Sonnet (D-05) or, for Free-only pins, fails it as `private_blocked`, so the guard fails closed (D-09).

**New DB test:** "opt-in switched off during an approval wait". A free child is created under a `saw_private` parent while the opt-in is on, then suspends on `create_issue`. The test switches the opt-in off, approves, and resumes. The next turn must go to Sonnet with a `private` route event.

### WR-01: Whitespace-only text blocks from the free model

**Files modified:** `src/server/agents/openrouter.ts`, `tests/unit/openrouter.test.ts`
**Commit:** b20750c
**Applied fix:** The adapter now keeps a text block only when `text.trim()` is non-empty. A `"\n\n"` before `tool_calls` therefore no longer reaches history, where Anthropic would reject it after a switch. A whitespace-only answer with no tool calls still raises `empty`, which falls back to Sonnet as before. The optional loop-side stripping was skipped: Anthropic turns never produce these blocks, so the adapter is the only source.

**New unit test:** a `"\n\n"` block followed by a tool call yields only the `tool_use` block.

### WR-02: Routing continues after a 401/402

**Files modified:** `src/server/agents/routing.ts`, `src/server/agents/loop.ts`, `tests/db/routing-loop.test.ts`
**Commit:** ded99ab
**Applied fix:**
- `hasFreeKey` now also requires `connections.status = 'connected'`.
- A free-turn 401 now calls `markFreeUnavailable`, as 429 and 402 already did.

**Side effects:**
- When the key is in the error state, the Command Centre picker treats it as having no key, because `queries.ts` uses `hasFreeKey` too.
- Routing stays off until the owner re-saves the key, since `saveOpenRouterKey` resets the status to `connected`. After a 402, this means re-saving the key once credit is topped up.

**DB tests:** the existing 401 test now also asserts that the cooldown is active. A new test checks that a key marked `error` makes a `simple` child skip the free model.

### WR-03: Free-model timeouts use up the 120 s run budget

**Files modified:** `src/server/agents/openrouter.ts`, `tests/unit/openrouter.test.ts`
**Commit:** 98fdb5f
**Applied fix:** `FREE_TIMEOUT_MS` was lowered from 45 s to 25 s. In the worst case, the first attempt times out, the 5 s backoff runs, and the retry times out, which takes 55 s. That leaves Sonnet at least 65 s of the 120 s `RUN_LIMITS.activeMs`, more than half.

**Why this option:**
- It is a one-constant change.
- It keeps the D-06 retry on timeouts exactly as decided.
- `activeMs` stays an accurate measure of wall time, which the review's first suggestion (not counting failed free time) would break. The run duration shown in activity also comes from `activeMs`.
- CONTEXT leaves the exact timeout values to Claude's discretion.

The review's third option, a retry gated on the remaining budget, adds a branch and isn't needed while the cap holds.

**Trade-off:** a slow but healthy free endpoint that needs more than 25 s for one non-streamed turn now falls back to Sonnet. That is safe, but it costs money.

**New unit test:** pins the invariant `2 * FREE_TIMEOUT_MS + 5000 <= RUN_LIMITS.activeMs / 2`, so raising either value can't silently bring the problem back.

### WR-04: Any 404 turns off `data_collection: "deny"` for 10 minutes

**Files modified:** `src/server/agents/openrouter.ts`, `tests/unit/openrouter.test.ts`
**Commit:** c8fe1c6
**Applied fix:**
- The error body is now parsed once by a local `errDetail`.
- On a 404, the deny preference is dropped and the request retried only if the code and message match `/data.?policy|data_collection|privacy/i`. OpenRouter's message reads "No endpoints found matching your data policy … settings/privacy".
- Any other 404, such as an unknown or retired model id, is now a plain non-transient `http` error, and the next request still sends `deny`.
- The parsed detail is reused for the error message, still capped at 200 characters.

**Tests:** the existing 404 tests now use a data-policy body. A new test covers the unknown-model 404: one call only, and `deny` is kept on the next request.

**To verify on the VM:** the exact wording of OpenRouter's data-policy 404 hasn't been checked live. If it doesn't match the pattern, the 404 surfaces as an error and the run falls back to Sonnet. That fails safe for privacy but costs money. Confirm it during the live smoke test.

### WR-05: A timeout while reading the body is classed as `bad_body`

**Files modified:** `src/server/agents/openrouter.ts`, `tests/unit/openrouter.test.ts`
**Commit:** 9bc24bf
**Applied fix:** In the `catch` around `res.json()`:

- A `TimeoutError` `DOMException` becomes `FreeModelError("timeout", true)`, so the D-06 retry and the cooldown now apply.

**New unit test:** a stalled body that throws `TimeoutError` gives a transient `timeout`. A garbled body still gives `bad_body`.

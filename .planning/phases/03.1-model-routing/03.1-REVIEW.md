# Phase 03.1: Code Review Report

**Reviewed:** 2026-10-09
**Depth:** standard
**Files Reviewed:** 31 (list above; drizzle meta snapshot/journal checked for consistency only)
**Status:** issues_found

## Summary

I reviewed the model-routing changes from `f3720c2..HEAD`, focusing on D-09 privacy, per-turn pricing and the spend cap, OpenRouter key handling, error and abort handling, and the migration.

**What holds up:**
- **Pricing (D-14/15).** Pricing per turn is correct. `model` is captured before each turn, and `addUsage(u, model)` writes both `agent_runs.cost_usd` and a `run_turns` row. Failed free turns are $0. The partial-stream estimate is applied only to paid models.
- **OpenRouter key.** The key is handled cleanly. It is sent only to the constant `openrouter.ai` URLs. Only `last4` is audited or returned in DTOs. No log line contains the key. Route-event reasons carry error codes, not OpenRouter's error text.
- **D-09 with the toggle off the whole time.** I found no leak:
  - The loop re-scans the whole conversation for private or unknown repo names before every free turn.
  - Every GitHub tool output contains the repo full name or URL.
  - Taint across the tree and thread (`privateInTree`) is checked when child runs are created.
  - Bad free turns are dropped before they reach history.

**Main problem (CR-01):** taint across the tree is only checked when the run is created. The guard inside the loop matches names only. A free run created while the toggle was on, and resumed after the owner turns it off, can still send private content to the free model. Approvals can wait indefinitely, so this window is real. The owner has the toggle on in production today, which makes switching it off the exact path that must work.

## Critical Issues

### CR-01: The loop's D-09 guard ignores tree and thread taint, so private content leaks after the toggle is switched off mid-run or during an approval wait

**File:** `src/server/agents/loop.ts:261` (with `src/server/agents/loop.ts:63`, `src/server/agents/routing.ts:47-61`)
**Issue:** `createRun` uses `privateInTree()` to block or redirect a free run only when the run is created, and only if `privateOk` is false at that moment. Before each turn, the in-loop guard checks only `mentionsSensitive(messages, names)`, which is a substring match on repo full names.

The leak path:
1. With the toggle on, the orchestrator delegates a `simple` task to the projects agent.
2. The task text includes private content copied from a sibling child's answer, without the `owner/repo` string (e.g. "summarise these PR titles: …").
3. `privateTainted` is true, but `privateOk` is true, so the run is routed to the free model. `taint()` also matches names only, so it never sets `saw_private` for this child.
4. The free model proposes `github.create_issue`, and the run suspends on approval. It can wait for days.
5. The owner switches the toggle off, then approves.
6. `advance()` resumes. The guard at line 261 finds no full name in `messages`, and the next free turn sends the private task text to the free model.

The same gap applies to any free run that is still in flight when the toggle is switched off. This breaks the D-09 rule that private content never reaches a free model when the toggle is off.

**Fix:** Re-evaluate the tree taint inside the guard, and treat the run's own flag as taint:
```ts
if (isFree(curModel) && !(await getFreePrivateOk(h))) {
  const treeTainted = tainted || (await privateInTree(h, run0.parentRunId ?? run0.id));
  if (treeTainted || mentionsSensitive(messages, await sensitiveRepoNames(h))) {
    const s = await switchToSonnet("private", "private repo data");
    if (s) return s;
    continue;
  }
}
```
Add a test for this case: create a child under privateOk=true with a parent marked `saw_private`, flip the toggle off, then `advance()`. It should switch to Sonnet before calling the LLM.

## Warnings

### WR-01: A whitespace-only text block from the free model is kept, and Sonnet then rejects it with a 400 after a switch

**File:** `src/server/agents/openrouter.ts:143-144`, `src/server/agents/loop.ts:334,342`
**Issue:** `if (text) content.push({type:"text", text})` accepts `"\n\n"`. Many OpenAI-style models emit exactly that before `tool_calls`. `checkFreeTurn` returns `null` as soon as `uses.length > 0`, so the turn is pushed into `messages`. If the run later switches to Sonnet (private taint, escalate or fallback), Anthropic rejects the history ("text content blocks must contain non-whitespace text"). The run then fails with `errorKind: "llm"`, which defeats D-05.
**Fix:** In the adapter, use `if (text.trim()) content.push(...)`. Optionally strip whitespace-only text blocks in `loop.ts` before `messages.push`.

### WR-02: After a 401 or 402, routing keeps sending simple tasks to OpenRouter, and every run pays a dead round-trip

**File:** `src/server/agents/routing.ts:63-66`, `src/server/agents/loop.ts:323`, `src/server/agents/llm.ts:56-59`
**Issue:**
- `hasFreeKey()` only checks that a `connections` row exists. A key marked `status: "error"` by `markConnectionError` (401 or 402) still counts as present.
- In the loop, `markFreeUnavailable` runs only for transient errors, 429 and 402. A 401 is not transient, so no cooldown is set.

As a result, every `simple` delegation sends a request that is bound to fail, then falls back. That doubles latency, adds a "Fell back" event to every run, and keeps going until the key is rotated.
**Fix:** Have `hasFreeKey` filter on `status = 'connected'`, i.e. `where(and(eq(connections.id,"openrouter"), eq(connections.status,"connected")))`. Also call `markFreeUnavailable` for `fe.status === 401`.

### WR-03: Free-model timeouts use up most of the 120 s run budget, so the Sonnet fallback is likely to hit `limit:time`

**File:** `src/server/agents/openrouter.ts:5`, `src/server/agents/loop.ts:316-321`, `src/server/agents/registry.ts` (`RUN_LIMITS.activeMs = 120_000`)
**Issue:** The cost of a fallback adds up as follows:

| Step | Time |
|---|---|
| First free attempt times out | 45 s |
| Retry-after backoff | up to 5 s |
| Retry times out | 45 s |
| **Added to `active` before Sonnet's first turn** | **about 90–95 s** |

That leaves Sonnet about 25–30 s for possibly several turns plus tool calls. A run that falls back for the very reason D-06 exists (a timeout) is then likely to be killed as "took too long", even though Sonnet could have finished it.
**Fix:** Do not count time spent on failed free attempts towards `activeMs`; drop the `active +=` on line 316 and on the dropped-turn path. Alternatively, lower `FREE_TIMEOUT_MS`, or retry on timeout only when the remaining budget can cover a Sonnet completion.

### WR-04: Any 404 turns off `data_collection: "deny"` for every request for 10 minutes

**File:** `src/server/agents/openrouter.ts:105-109`
**Issue:** A 404 is treated as "no endpoint honours the deny policy". OpenRouter also returns 404 for an unknown or retired model id, and free model ids are retired often. Any such 404 sets `denyUnsupportedUntil`, and for the next 10 minutes all free requests go out without the no-logging preference. With the private toggle on in production, private repo content then goes to endpoints that may log or train on it, even though deny-compatible endpoints exist. D-10 asks for the deny preference wherever it can be honoured.
**Fix:** Only back off when the 404 body names the data policy, e.g. `/data policy|data_collection/i` on `error.message`. Otherwise treat the 404 as an ordinary non-transient `http` error. Parse the body once and reuse it for both the check and the `detail`.

### WR-05: A timeout while reading the response body is classed as non-transient `bad_body`, so the D-06 retry is skipped

**File:** `src/server/agents/openrouter.ts:126-131`
**Issue:** `AbortSignal.timeout(45s)` also covers `res.json()`. If the headers arrive but the body stalls, the `TimeoutError` is caught as `bad_body` with `transient: false`. The run then goes straight to Sonnet without the one retry D-06 promises, and no cooldown is set.
**Fix:** In the `catch` around `res.json()`, check for `e instanceof DOMException && e.name === "TimeoutError"` (and that the caller signal is not aborted), and throw `new FreeModelError("timeout", true)`.

## Info

### IN-01: The `saw_private` backfill only scans `prompt` and tool outputs

**File:** `drizzle/0002_model_routing.sql:22-23`
**Issue:** The backfill does not scan `agent_runs.messages` (thread history, assistant text), `answer` or `thread_messages`. This is mostly covered because child tool outputs carry full names. Older runs whose only exposure was via history are still not flagged.
**Fix:** Also match against `r."messages"::text` and `r."answer"`. This is cheap, one-off and fails closed.

### IN-02: `run_turns.seq` has no unique constraint

**File:** `drizzle/0002_model_routing.sql:1-12`, `src/server/agents/loop.ts:283`
**Issue:** `seq` is computed with `max(seq)+1`. Turns are sequential per run today, but nothing enforces it.
**Fix:** Add `uniqueIndex().on(t.runId, t.seq)` in a later migration if `seq` is ever relied on.

### IN-03: Retrying a `private_blocked` run shows a generic "Try again" message

**File:** `src/shell/ai/result-card.tsx:25`, `src/agents/run-detail.tsx:115`
**Issue:** `retryRun` returns `code: "private_blocked"` for an agent pinned to Free only in a tainted tree. The UI shows "Couldn't start another run. Try again.", and trying again will always fail.
**Fix:** Map `private_blocked` to the same copy that `loop.ts:229` uses.

### IN-04: Route steps are unsorted when thread detail first loads

**File:** `src/server/agents/chat.ts:65`
**Issue:** `steps = [...toolSteps, ...routeSteps]` is not sorted, so the "Routed" step (seq 0) shows after the tool steps until a live event re-sorts the list in `chat-state.ts`.
**Fix:** Add `.sort((a, b) => a.seq - b.seq)`, as `queries.ts` already does.

### IN-05: The Settings copy is wrong for agents pinned to Free only

**File:** `src/settings/connections-section.tsx:160`
**Issue:** The copy says "any run that touches a private repository switches to Claude Sonnet". Runs pinned to Free only fail with `private_blocked` instead (`loop.ts:224-231`).
**Fix:** Change it to "…switches to Claude Sonnet (or stops, for agents set to Free only)".

### IN-06: The model picker can show "Auto"/"Free only" with no key, and orchestrator pins are accepted but ignored

**File:** `src/server/agents/routing.ts:41-44`, `src/server/agents/runs.ts:30-34`
**Issue:**
- `effectivePref` returns a stored `"auto"` or `"free"` even when `hasKey` is false. Runs then use `defaultModel`, but the picker shows a disabled "Free only" option as selected.
- `setAgentModel` still accepts a Sonnet or Haiku pin for `orchestrator`, which `resolveModel` silently overrides with Opus.

**Fix:** Have `effectivePref` return `defaultModel` when `!hasKey`. Have `setAgentModel` reject any value for `orchestrator`.

### IN-07: A provider-reported cost on a `:free` model is charged at Opus token rates

**File:** `src/server/agents/pricing.ts:78`
**Issue:** This over-counts on purpose (D-14 guard), so it is acceptable. Note that `usage.cost` is only parsed if OpenRouter includes it; the request does not ask for `usage: { include: true }`. The guard may never fire, which is safe but makes it dead code in practice.
**Fix:** Either request usage accounting explicitly or drop `providerCostUsd`. Do not leave it half-wired.

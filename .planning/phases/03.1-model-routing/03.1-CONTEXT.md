# Phase 3.1: Model routing - Context

**Gathered:** 2026-10-09
**Status:** Ready for planning

<domain>
## Phase Boundary

Each delegated agent run goes to the cheapest model that can handle it. Routine work runs on a free OpenRouter model at US$0. Work that needs reasoning, and any free-model failure, goes to claude-sonnet-5-5. The orchestrator always runs on claude-opus-5-5. Routing sits behind the existing `LlmClient` seam. It is visible per run in the trace and the Command Centre, and each agent can override it. With no OpenRouter key configured, LifeOS behaves exactly as it does today (Anthropic only). GitHub sync makes no LLM calls and is out of scope.

</domain>

<decisions>
## Implementation Decisions

### Routing rule
- **D-01:** **The orchestrator tags each delegation.** The `delegate` tool gets a `tier: "simple" | "reasoning"` field that Opus fills in. `simple` → free model, `reasoning` → Sonnet. The tag and its reason appear in the trace.
- **D-02:** **The tag is trusted, with no forced tier by tool.** Free models may also run APPROVE-tier tools such as `github.create_issue`. The owner still reviews every approval.
- **D-03:** **The free model is chosen during research.** Pick a free OpenRouter model with reliable tool calling, e.g. DeepSeek or Qwen `:free`. Keep the model id configurable rather than hard-coded in many places.
- **D-04:** **The per-agent override is one picker with four options: Auto / Free only / Sonnet / Opus.** It extends the existing Command Centre model picker (`agents.model`, where null means the registry default). Auto means tiered routing, which is the default for domain agents. The other three pin a model and turn routing off for that agent. The orchestrator is always Opus and not routed.

### Fallback & escalation
- **D-05:** **Fallback switches models mid-run and keeps the history.** From the failing turn onward, the run continues on Sonnet with the conversation so far, and tool results already fetched are reused. The run's current model changes, and the trace records the switch with its reason.
- **D-06:** **Retries:** 1 retry on the free model for transient errors (429/5xx/timeout), then Sonnet.
- **D-07:** **The free model can escalate itself.** In free runs it gets an `escalate` tool (reason: string). Calling it switches the run to Sonnet using the same mechanism as D-05, and the reason shows in the trace.
- **D-08:** **These triggers cause a fallback:** errors, timeouts, malformed or invalid tool calls (schema or zod failure, unknown tool), empty output, **plus a cheap sanity check**, i.e. inexpensive heuristics such as no tool use on a question that clearly needs data, or a final answer with no content. The planner defines the exact heuristics. They must stay deterministic and cheap, with no extra LLM judge call.

### Privacy of free models
- **D-09:** **Private-repo data needs an opt-in.** Free models may receive all synced GitHub data only when a Settings toggle is on. The toggle is labelled roughly "Allow private-repo content to be sent to free models (may be logged by provider)" and is **off by default**. When it's off, private-repo content must never reach a free model. Public-repo data may always go to free models.
- **D-10:** **Provider preference leans toward no logging but doesn't require it.** Set OpenRouter provider preferences that avoid data collection or training where free endpoints allow it (e.g. `provider.data_collection: "deny"`), and fall back to the D-09 gate if no endpoint qualifies. Research must confirm the current OpenRouter parameters and which free endpoints honour them.
- **D-11:** Never send secrets or tokens to any model. That is existing behaviour (`redact.ts`) and must also hold on the OpenRouter path.

### Key, visibility & pricing
- **D-12:** **The OpenRouter key lives in Settings → Connections, encrypted** with AES-256-GCM like the GitHub PATs (Phase 3 D-09). Only the last 4 characters are shown. It can be rotated without a redeploy, and connection status is visible. If the key is absent, routing is off and every run uses its Anthropic model as today.
- **D-13:** **Visibility:** each run gets a model chip showing the final model, plus route and switch events in the trace (e.g. "routed: free (tag simple)", "fell back → Sonnet: timeout", "escalated → Sonnet: <reason>"). The Command Centre shows the model per run and free vs paid run counts.
- **D-14:** **Pricing:** OpenRouter `:free` models cost $0. Any other OpenRouter model id falls under the existing unknown-model rule and is priced as Opus, so the cap is never under-counted. **Cost is computed per turn using that turn's model**, because a run can switch mid-way. Today `loop.ts` prices with `run0.model`, and that must change.
- **D-15:** **At the cap, the existing D-14/15 block applies to all runs.** There is no free-only mode at the cap.

### Claude's Discretion
- Which free model to use, and the exact timeout values.
- How to enforce D-09 while the toggle is off. The preferred approach is for the gateway to read repo `private` from the sync tables: when a free run's tool result contains private-repo data, the run switches to Sonnet before the next LLM turn (D-05 mechanism). Filtering out private rows is the alternative. The planner picks whichever is safer and simpler, and the result must be that no private content reaches a free model.
- How Anthropic tool and message formats translate to OpenAI/OpenRouter chat formats behind `LlmClient`, either hand-rolled or via an already-installed SDK. Avoid new dependencies where a small adapter is enough.
- The exact sanity-check heuristics (D-08).

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `LlmClient` interface: add an OpenRouter-backed client and a routing client that picks per turn. Existing route tests mock `llm.ts`.
- `ToolContext.llm`: the injection point that tests already use.
- The encrypted connection storage and the ConnectionRow UI from Phase 3 (GitHub PATs).
- Command Centre model picker: extend it with "Auto" and "Free only".

### Established Patterns
- `LlmTurn` returns Anthropic `ContentBlock[]`, so the OpenRouter client has to translate OpenAI responses (tool_calls) into Anthropic tool_use blocks, and translate tools and messages the other way.
- The spend cap is a summed `costUsd` per run in Postgres, and the unknown-model fallback is Opus price.
- Trace events stream to the AI panel as `ChatEvent`s, so route, fallback and escalate events plug in there.

### Integration Points
- The `delegate` tool schema (tier) and the orchestrator system prompt (instruct Opus how to tag).
- The run record has to store the current/final model and per-turn model so the pricing and the UI chip are correct.
- Settings → Connections gets the OpenRouter key row and the private-data toggle.

</code_context>

<specifics>
## Specific Ideas

- Example of a simple task: the Projects agent listing or summarising synced repos, PRs, issues and commits.
- Examples of reasoning tasks: multi-step analysis, drafting an issue, ambiguous asks. The orchestrator tags these, but per D-02 the tag is trusted rather than enforced by tool tier.
- Escalate tool: the free model hands off with a short reason, and the reason shows in the trace.

</specifics>

<deferred>
## Deferred Ideas

- A free-only mode when the spend cap is reached (would need a non-Opus orchestrator path). Rejected for now.
- Using OpenRouter-reported cost instead of local pricing. Rejected for now in favour of the $0/Opus-price rule.

</deferred>

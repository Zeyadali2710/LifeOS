## Summary

The seam is smaller than it looks. `LlmClient.stream({model, ...})` already takes the model per call, and messages are persisted in Anthropic format. So: (1) make `getLlm()` return a thin **dispatching client** that sends `:free`-suffixed model ids to a hand-rolled OpenRouter adapter (plain `fetch`, non-streaming) and everything else to the Anthropic client; (2) put all routing/fallback state in `loop.ts` (it owns history, DB, events, pricing), tracked as a mutable `curModel` that is persisted to `agent_runs.model` on every switch. Because history is Anthropic-shaped and translated per call, switching to Sonnet mid-run is free (D-05).

Fallback = "drop the offending free turn, set `curModel = sonnet`, `continue` the loop" (do not push the bad assistant turn into `messages`; this also handles `escalate`, invalid tool calls, failed sanity checks uniformly).

Current-state findings that matter: **no DeepSeek or Qwen `:free` model exists right now** (checked live catalog). Recommended default is `nvidia/nemotron-3-super-120b-a12b:free`, backup `google/gemma-4-31b-it:free`. Free tier limits are tight (20 rpm; 50 req/day unless >= $10 credits ever bought, then 1000/day), so 429 fallback will be common without credits; add a short in-memory cooldown.

**Primary recommendation:** dispatching `LlmClient` + hand-rolled `fetch` OpenRouter adapter (non-streaming, no new deps); loop-owned `curModel` with a single `switchToSonnet(kind, reason)` helper; new `run_turns` table for per-turn model/cost; D-09 enforced by a fail-closed pre-turn scan of tool results for private (or null-`private`) repo full names, escalating to Sonnet.

## OpenRouter API facts [CITED: openrouter.ai/docs/api-reference/chat-completion, /guides/features/tool-calling, /api-reference/limits, /guides/routing/provider-selection]

- `POST https://openrouter.ai/api/v1/chat/completions`, header `Authorization: Bearer <key>`, `Content-Type: application/json`. (Optional `HTTP-Referer`/`X-Title` attribution headers; skip.) Key check: `GET https://openrouter.ai/api/v1/key` (documented in limits page) - use it for validate-on-save.
- Request: `{model, messages, tools:[{type:"function",function:{name,description,parameters}}], tool_choice:"auto", stream:false, max_completion_tokens, provider:{data_collection:"deny", require_parameters:true}}`. `max_tokens` is documented as deprecated -> use `max_completion_tokens`. `tools` must be re-sent on every request including follow-ups.
- Assistant tool call response: `choices[0].message.tool_calls[] = {id,type:"function",function:{name,arguments:<JSON STRING>}}`, `finish_reason:"tool_calls"`; content may be null. Return results as one `{role:"tool", tool_call_id, content:string}` message per call, after the assistant message (which has `content:null` + `tool_calls`).
- `finish_reason` values: `tool_calls`, `stop`, `length`, `content_filter`, `error` (last three only listed, not described). Treat anything but tool_calls/stop as failure.
- `usage`: `prompt_tokens`, `completion_tokens`, `total_tokens`, `cost`. `parallel_tool_calls` defaults true for most models; keep default and handle N calls.
- Errors: body `{error:{code,message,metadata?}}`. 400 bad params; 401 bad key; **402 credits (even for free models if account balance negative; `metadata.limit_source`)**; 403 guardrail; **404 also returned when no endpoint satisfies routing constraints**; 408; 413; 422; 429 (platform or upstream; honour `Retry-After`); 500/502/503/524/529 upstream. Mid-stream errors arrive as SSE (avoided by non-streaming).
- Provider object field names confirmed: `order`, `only`, `ignore`, `sort`, `allow_fallbacks`, `require_parameters`, `data_collection`, `zdr`, `max_price`.
- Free rate limits: 20 req/min; 50 req/day if < $10 credits ever purchased, 1000/day if >= $10.

### Privacy / data_collection (D-10) - LOW confidence
- `provider.data_collection:"deny"` restricts to providers that don't store/train on prompts. The endpoints API exposes **no data-policy field**, so which free endpoints qualify cannot be determined without a live request. Expect many free endpoints (e.g. Google AI Studio free tier) to be excluded; a 404 on every request is plausible. [ASSUMED]
- Recommended behaviour: send `data_collection:"deny"`; on **404 only**, retry the same request once without `data_collection` (safe because the D-09 gate has already guaranteed that only public data, or owner-approved private data, is in the prompt). Cache "deny unsupported" in module memory for ~10 min to avoid doubling calls. Record which variant answered in the route event/logs. Do not use `zdr` (unnecessarily strict for free).
- Account-level OpenRouter privacy settings (free models are configured separately) can also block free routing -> would show as 404; same retry handles it, and final failure falls to Sonnet. Owner should be told in Settings copy: "free models may log prompts".

## Architecture Patterns

### Flow
```
Opus (orchestrator) --delegate{agentId,task,tier,tierReason?}--> createRun(tier)
   resolveModel(agentCfg, tier, hasOrKey) -> run.model (free id | sonnet | opus | agent default)
   advance(): curModel = run.model
     loop turn:
       if isFree(curModel): gate D-09 scan (toggle off) -> private? switch(sonnet,"private_data")
       call llm.stream({model:curModel, tools: +escalate if free})
          dispatching client: ":free" -> openrouter.ts (translate msgs/tools) ; else anthropic
       free + error: transient -> retry once -> else switch(sonnet,reason)
       free + turn invalid/escalate/sanity-fail -> drop turn, switch(sonnet,reason), continue
       else: addUsage(curModel) -> run_turns row + agent_runs totals; push turn; run tools; push results
   switch(): update agent_runs.model, append route_events, emit {k:"route"}, curModel=sonnet (never back to free)
```

### Files

### Dispatch (llm.ts)
`getLlm()` currently returns `null` when no Anthropic key (runQueued then fails "no_key"). Keep that: dispatcher is null iff no Anthropic key. OR client takes `getKey: () => Promise<string|null>` that reads+decrypts the `connections` row `openrouter` per `stream()` call (rotation w/o redeploy; D-12). If key missing it throws `FreeModelError("no_key", permanent)` - but `resolveModel` should already avoid free when no key (check key presence once at createRun and again in advance so a deleted key mid-run falls back to Sonnet).

### Translation (Anthropic <-> OpenAI), all in `openrouter.ts`
- system: prepend `{role:"system", content: p.system}` (drop `cache_control`).
- assistant message: text blocks joined -> `content` (or `null`), `tool_use` -> `tool_calls[{id, type:"function", function:{name, arguments: JSON.stringify(input)}}]`.
- user message: `tool_result` blocks -> one `{role:"tool", tool_call_id: tool_use_id, content}` each, in the order of the preceding assistant `tool_calls` (all tool messages must follow the assistant message directly); `is_error` -> content `"Error: "+content`. Any plain text/user string -> `{role:"user"}`, emitted after the tool messages.
- tools: `{type:"function", function:{name, description, parameters: input_schema}}`.
- response: `content` string -> `{type:"text", text, citations:null}` block; each `tool_calls[i]` -> `{type:"tool_use", id, name, input}`. **Always generate the tool_use id** (`call_or_${randomUUID().slice(0,12)}`): provider ids can be missing/duplicate/contain chars Anthropic rejects when history later goes to Sonnet, and `tool_calls` idempotency is keyed on `(runId, toolUseId)`.
- `JSON.parse(arguments)`: empty string -> `{}`; parse failure or non-object -> throw `FreeModelError("invalid_tool_call")` (loop falls back; bad turn never stored).
- stopReason map: `tool_calls`->`tool_use`, `stop`->`end_turn`, `length`->`max_tokens`; `content_filter`/`error`/null/other -> throw `FreeModelError("bad_finish")`.
- usage: `{input: prompt_tokens, output: completion_tokens, cacheWrite:0, cacheRead:0}`; missing usage -> estimate chars/4 (tokens still count toward `RUN_LIMITS.tokens`). Ignore `message.reasoning` (do not store or forward).
- Timeout: `AbortSignal.any([signal, AbortSignal.timeout(45_000)])` for free calls (recommended; free endpoints can queue). Abort by the caller (`signal.aborted`) must NOT be treated as free failure - rethrow.
- Error classification in `FreeModelError`: `transient = status in {408,429,500,502,503,524,529} || timeout`; permanent = 401/402/403/400/404(after retry)/422/invalid body. Retry once only if transient (D-06); on 429 honour `Retry-After` capped at 5 s.

### Loop changes (loop.ts, minimal diff)
1. `let curModel = run0.model;` use in `stream()` and `addUsage(u, curModel)` -> `costUsd(curModel, u)` (fixes lines ~195/202). `addUsage` also inserts a `run_turns` row.
2. Strip-before-push validation for free turns (before `messages.push(assistant)`): allowed names = `allowed` api names + `escalate`; each `tool_use.name` must exist, `input` must `safeParse` against that tool's zod schema (pre-validation here is cheap; gateway still re-validates). Failure -> fallback `invalid_tool_call`.
3. `escalate` tool: defined in `routing.ts` (`{name:"escalate", description:"Hand this task to a stronger model when you cannot do it reliably", input_schema:{reason:string maxLength 200}}`), appended to `anthropicTools` only when `isFree(curModel)`. It is **not** in `TOOLS`/gateway/permissions. If a free turn contains it, discard the whole turn (no tool executed, even siblings), switch to Sonnet, `continue`.
4. `switchToSonnet(kind: "fallback"|"escalated"|"private", reason)`: `UPDATE agent_runs SET model=sonnet, route_events = route_events || event`, `notifyLive`, `emit({k:"route", ...})`, `curModel = MODELS.sonnet`. One-way; never returns to free in the same run. Resume after approval uses persisted `run.model`, so a switched run stays on Sonnet; a still-free run keeps the gate/validation on.
5. Failed free call with partial usage: non-streaming means no partial billing; free costs $0, so skip the existing streamed-chars estimate for free.
6. Retry counter: `freeRetried` boolean in the turn loop (1 retry per run per D-06 reading "1 retry ... then Sonnet"; per-turn would multiply 429s against the 20 rpm cap). Recommend per-run.
7. In-memory cooldown: after a free call fails with 429/402 (post-retry), mark `freeUnavailableUntil = now+5min` (module level); `resolveModel` returns Sonnet during cooldown for Auto. Avoids burning one failed request per run when the 50/day cap is exhausted.
8. Free turns still go through `RUN_LIMITS` (tokens, tool calls, time). Per-turn `maxTokens` unchanged.

### Model resolution (new, runs.ts or routing.ts)
```ts
export type AgentPref = "auto" | "free" | string; // agents.model: null|"auto"|"free"|claude id
function resolveModel({pref, agent, tier, orKey, cooldown}): string {
  if (agent.id === "orchestrator") return MODELS.opus;                 // never routed, ignores pref
  const p = pref ?? (agent.routable && orKey ? "auto" : agent.defaultModel);
  if (p === "free")  return orKey ? FREE_MODEL : agent.defaultModel;   // pinned
  if (p === "auto")  return orKey && !cooldown && tier === "simple" ? FREE_MODEL : MODELS.sonnet;
  return p;                                                            // sonnet / opus pinned
}
```
- Add `routable: true` to the `projects` AgentDef (client-importable file; keep no server imports). Auto with no `tier` (top-level chat run of a domain agent, or retry) -> Sonnet (safe).
- `createRun` gets `tier?: "simple"|"reasoning"`; store `agent_runs.tier`. `retryOf` runs: copy the old run's tier.
- `setAgentModel` allowlist expands to `[...Object.values(MODELS), "auto", "free"]`; picker options per D-04. Hide/disable Auto and Free options when no OR key. `queries.ts` `config.model` returns raw value; DTO also returns `orConnected` so the UI can disable.
- "Free only" (pinned): recommendation = **no Sonnet fallback** - failures and the D-09 gate fail the run with `errorKind:"free_unavailable" | "private_blocked"`, because the owner pinned the model. This is an interpretation of D-04 ("turn routing off"); see Open Questions.

### D-09 enforcement (recommended: pre-turn scan, fail closed, escalate)
Where data enters: GitHub read tools query sync tables (`github_repos`, `_pull_requests`, `_issues`, `_commits`, `_workflow_runs`) and emit repo identity as `owner/repo` strings (`ref: "owner/repo#12"`, `repo: fullName`, list_repos `repo`). `github_repos.private` is a nullable boolean per row [VERIFIED: schema.ts]. Pattern:

- Before every free LLM call, if toggle `ai.free_private_ok` is not `true`: load `sensitive = fullName of repos WHERE private IS NOT FALSE` (null treated as private - fail closed); stringify the `tool_result` blocks in `messages` (case-insensitive substring of each sensitive `fullName`). Any hit -> `switchToSonnet("private", ...)` (D-05 path). One cheap query + string scan per free turn; repo count is small (single owner).
- Why not row filtering: would require touching every tool, hides data silently (wrong answers, e.g. counts), and misses any future tool; the scan is tool-agnostic and keeps tools untouched.
- Consequence to surface to the owner: with the toggle off, any free run whose tool output mentions a private repo (including `list_repos` for an owner with private repos) escalates to Sonnet after that tool call. The $0 path then applies mainly to public-repo questions. This is inherent to D-09 as locked.
- Residual (document, accept): the `task` text written by Opus and the user prompt could mention a private repo name (metadata only, not content); the scan covers tool results only. Also data-less repo *names* in `list_repos` are treated as private data (conservative).
- Plan check: `ci_status`/`get_pull_request` also emit `repo:`/refs from `fullName` (verified `repo: r.fullName` at github.ts) - planner must grep every tool's output builder to confirm no tool emits a repo's content without its full name (e.g. only short `name`).
- Toggle persistence: `settings` row key `ai.free_private_ok` (value boolean), server action `setFreePrivateAction` mirroring `setSpendCapAction` (`requireOwner`, zod boolean, `audit({action:"settings.free_private", metadata:{value}})`). Read per advance (and per free turn is fine).

### D-08 sanity heuristics (deterministic, free runs only, evaluated on the turn before it is stored)
1. Invalid tool call: unknown name, zod `safeParse` failure, or unparseable arguments JSON.
2. Empty final: no tool_use and `answer.trim().length < 2`.
3. Needs-data-but-no-tool: no tool_use, `toolCount === 0` for this run, and agent has `requiresTools: true` in registry (set on `projects`). (Prefer a registry flag over a keyword regex; zero false positives for the only live domain agent.)
4. Unsupported citations: final answer contains refs matching `/\b[\w.-]+\/[\w.-]+#\d+\b/g` that don't appear verbatim in any `tool_result` text of this run (hallucinated PR/issue ids).
5. Tool-markup leak: final text matches `/<tool_call>|<function=|"tool_calls"\s*:|^\s*\{\s*"name"\s*:/i` (model printed a call instead of making one).
6. Duplicate call: identical `(name, canonical input)` as a previous call in this run (loop guard).
7. `finish_reason:"length"` (truncated) or `content_filter`/`error`.
All map to `fallback` with a machine reason code (`invalid_tool_call`, `empty`, `no_tool_use`, `unsupported_ref`, `tool_markup`, `repeat`, `truncated`) shown in the trace.

## Common Pitfalls
1. **Pushing a bad free turn into history.** Later Sonnet call 400s on orphan tool_use/results. Validate before `messages.push`; drop the turn on fallback.
2. **Provider tool-call ids** reused/malformed -> always regenerate ids; the same ids must be used in both `tool_use` and the `tool` message translation (derive from stored history, not from fresh ids).
3. **`tool` messages must follow the assistant `tool_calls` message immediately**, one per call, and every call needs an answer (pending/approval cases: `buildToolResults` already answers every id).
4. **Pricing with `run0.model`** after a switch -> use `curModel`; test mixed-run cost.
5. **`spendByModel` groups by run model** -> mixed runs misreport; move to `run_turns`.
6. **Resume after approval** reads `claimed.model`: switch must be persisted before suspend/finish, else resumed run restarts on free (and could re-send private data; the gate also re-runs, belt and braces).
7. **Abort vs timeout:** distinguish caller abort (rethrow, existing behaviour) from the 45 s timeout (fallback).
8. **429 daily cap exhausted** (50/day w/o credits) makes every run waste a call; use cooldown (Loop #7). `docs` / Settings copy should recommend buying >= $10 credits once for the 1000/day cap (credits not spent on free models).
9. **402 on free models** if the OR account balance is negative: permanent -> Sonnet; surface in connection `lastError`.
10. **`null` repo `private`** must be treated as private.
11. **Cooldown/state is per process** (web vs worker). Acceptable (`ponytail:` comment).
12. **Next.js:** AGENTS.md says this Next has breaking changes; this phase only adds a `"use server"` action mirroring existing `settings-actions.ts` and client components, no new route handlers. `node_modules/next/dist/docs/` exists (01-app ...); planner/executor should skim server-actions docs only if deviating from the existing action pattern. ## Open Questions (RESOLVED)
1. **"Free only" semantics** - RESOLVED (owner, via orchestrator): no fallback. A pinned Free-only run fails (`free_unavailable` / `private_blocked`) and the reason is recorded in the trace as a "blocked" route event. Pinned runs are not given the `escalate` tool.
2. **Owners with private repos** - RESOLVED: D-09 enforced literally and fail closed, with two layers: (a) a per-turn whole-conversation scan in every free run for private/null-private repo names; (b) a thread-level taint: any run whose tool results mention a private repo sets `agent_runs.saw_private`, and a delegation from a run tree/thread containing such a run never starts on free (Auto -> Sonnet "private data in thread"; Free only -> `private_blocked`). This closes the "Opus paraphrases private content into the task" gap. Owners with private repos will often run on Sonnet; accepted.
3. **Backfill `run_turns`** - RESOLVED: backfill one turn per existing billed run in migration 0002.
4. **Haiku / verification** - RESOLVED: Haiku stays in the `MODELS` allowlist (an existing setting stays valid), but the picker offers only the four D-04 options. Free-model tool-call reliability (A2) is verified by a live OpenRouter smoke test on the homelab VM in plan 09.

## Security Domain (ASVS L1)
| ASVS | Applies | Control |
|------|---------|---------|
| V2/V3 | existing | `requireOwner()` on new server actions |
| V4 Access Control | yes | server actions owner-only; `escalate` cannot grant tools or raise to Opus; permissions/tier policy unchanged for all models |
| V5 Input Validation | yes | zod for `tier`, `tierReason` (<=200), toggle boolean, key length; pre-validate free-model tool inputs |
| V6 Cryptography | yes | reuse `crypto.ts`; never hand-roll |
| V7 Logging | yes | no key/headers/bodies in logs; audit key and toggle changes |
| V8 Data Protection | yes | D-09 gate, D-11 redaction, `data_collection:"deny"` best effort |

| Threat | STRIDE | Mitigation |
|--------|--------|-----------|
| OR key leak (DB, logs, DTO) | Info disclosure | AES-256-GCM, last4 only, decrypt in-memory per call, never in `ConnectionDTO`/errors; OR error messages truncated before storing in `lastError` |
| Private repo data to free provider that logs/trains | Info disclosure | fail-closed pre-turn scan; null=private; toggle default off; Settings copy states logging risk |
| Prompt injection via `escalate.reason` / tool data steering the free model | Tampering/EoP | escalate only moves to Sonnet (same tools/policy/approvals); reason is untrusted text: truncate, render as plain text, never put in system prompt or give to Sonnet as an instruction; DATA_RULE retained; APPROVE-tier tools still need owner approval (D-02) |
| Prompt-injected free model fabricates approval payloads | Tampering | approvals show payload hash (existing); owner reviews |
| Cost under-count (mixed providers) | Repudiation/DoS | per-turn pricing; unknown ids -> Opus; `usage.cost>0` on free -> Opus rate; `run_turns` audit trail; RUN_LIMITS apply to free turns |
| Free-model DoS of flow (429/outage) | DoS | one retry, cooldown, Sonnet fallback, per-call timeout |
| Malformed tool args executing | Tampering | zod validate before store and again in gateway |
| SSRF via model id/env | Tampering | OR URL is a constant; model id from env regex `:free`, never from model output |

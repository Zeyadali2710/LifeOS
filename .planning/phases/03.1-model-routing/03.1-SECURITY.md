# Phase 03.1 — Security

> Per-phase security contract: threat register, accepted risks, and audit trail.

Register built from the `<threat_model>` blocks of plans 03.1-01 to 03.1-09: 39 threats (38 mitigate, 1 accept). The evidence reflects the code after the review fixes CR-01 and WR-01 to WR-05 (03.1-REVIEW-FIX.md). Where a fix changed a mitigation, the current code is cited.

---

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| LifeOS server -> OpenRouter / free provider | Each free turn sends the conversation to a third party that may log it | Prompts and tool data (public repo data; private repo data only with the opt-in on) |
| OpenRouter response -> loop / tool gateway | Untrusted, possibly prompt-injected model output | Tool names, tool args, text, escalate reason |
| Free model output -> route event reason -> browser | Model-written text shown in the execution trace | Untrusted text, at most 200 chars |
| Opus tool call -> delegate input | Model-written tier, tierReason and task | Untrusted routing hints |
| Owner browser -> server actions | Key, toggle and model-picker values | OpenRouter API key (secret), boolean, enum |
| DB at rest | Encrypted OpenRouter key | AES-256-GCM ciphertext |
| Server -> openrouter.ai/api/v1/key | Key validation | API key in Authorization header |
| Migration -> production DB | One-off backfill on deploy | run_turns, saw_private |
| VM -> OpenRouter (live smoke test) | Real prompts to a free provider | Live repo data |

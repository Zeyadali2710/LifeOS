# Phase 5.1 — Security

> Per-phase security contract: threat register, accepted risks, and audit trail.
> Verified against the code on `main` (HEAD 201f6cb). This includes the 05.1-REVIEW-FIX changes (CR-01, CR-02, WR-01..WR-08, commits 87cae37..96cdd61) and commit 462d65c, which added `github.list_pull_requests` and `github.recent_commits` to `CONTENT_TOOLS`.

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| model -> draft payload | Agent-authored JSON, which may contain injected repo text, becomes an approval payload | untrusted structured data |
| model -> GitHub request | The model chooses the repo and path, which become a GitHub API URL called with the read PAT | untrusted path, credential use |
| GitHub -> model | Third-party repo files, trees, PR bodies, issue titles and commit messages enter the model context | untrusted text, possibly private |
| repo content -> agent tool calls | Text read from GitHub may steer the model toward writes | prompt injection |
| owner permissions overrides -> gateway | The owner may lower tool tiers | policy |
| browser -> approve / saveEdit actions | An owner-edited draft crosses to the server | untrusted until re-validated |
| approval -> worker execution | An approved payload runs with DB write access | integrity |
| repo-derived draft / stored context -> browser and Claude Code brief | Untrusted strings are displayed and copied | untrusted text |
| owner VM deploy -> production DB | Migration 0007 runs against live data | schema change |
| SUMMARY / UAT notes -> repo | Planning artifacts are committed | possible secrets |

## Residual Notes (informational, non-blocking)

- **N-1 (T-05.1-38):** docs/permissions.md:30-36 is out of date in the safe direction. It lists only `list_tree`/`get_file` as content tools and says the floor covers only the run tree. It also says later thread turns aren't floored. The code now floors six content tools across tree, thread and retries (policy.ts:11, 18-30). The docs should be updated, but the code is stricter than what they describe.
- **N-2:** The gateway floor counts content-tool rows in any status (gateway.ts:119-123), while `runSources` lists only `done` rows (projects.ts:110). A failed read can therefore trigger the floor without appearing in sources. This is the conservative direction.
- **N-3 (T-05.1-02):** The 50-entry `sources` bound is enforced by the schema (project-payload.ts:157) and by `runSources` `.slice(0, 50)` (projects.ts:124), but no unit test covers it.

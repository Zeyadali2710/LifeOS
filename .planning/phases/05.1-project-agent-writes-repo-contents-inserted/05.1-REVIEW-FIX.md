### CR-02: Editing a `project_update` approval wipes due date, priority and milestone

**Files modified:** `src/approvals/project-approval.tsx`, `tests/unit/project-approval-draft.test.ts`, `tests/db/project-agent-writes.test.ts`
**Commit:** 6340587 (fix + unit test), e3e7bda (DB round-trip test)
**Applied fix:** Each task and milestone row now keeps `init` (the value first shown) and `orig` (the draft's own value). If the owner leaves a field alone, `validateProjectDraft` sends `orig` back unchanged, so an absent field stays absent ("keep current") and is never turned into `null`. Only fields the owner actually changes are converted, and clearing a field still sends `null`. For update rows with an `id`, the form now shows current values from `before.tasks` / `before.milestones` when the draft leaves them out. Tests:
- Unit: a rename-only edit round-trips to `{id, title}`, and an explicit clear still clears.
- DB: an owner edit of a rename-only draft keeps `dueDate`, `priority` and `milestoneId`.

**Status:** fixed: requires human verification (logic)

### WR-01: Content floor scoped to the run tree, not the thread or retried runs

**Files modified:** `src/server/agents/policy.ts`, `src/server/agents/gateway.ts`, `tests/db/gateway.test.ts`
**Commit:** 8603e21
**Applied fix:** New `contentScope(runId)` SQL fragment. It covers the run's tree (self, parent, siblings, children), the run it retries and that run's parent, and every run in those runs' threads plus their children. This matches what `privateInTree` reaches. The gateway floor query uses it. A DB test confirms the floor triggers from an earlier thread run's child and from a retried run's tree; this test fails without the fix.

### WR-03: Lost update for tasks and milestones edited after drafting

**Files modified:** `src/server/agents/tools/projects.ts`, `src/server/agents/approvals.ts`, `tests/db/project-agent-writes.test.ts`
**Commit:** cfc7e5e
**Applied fix:** New exported `itemsChanged(h, before)`. It compares current task fields (title, dueDate, priority, milestoneId) and milestone fields (title, dueDate) against the `before` entries; a missing row counts as changed.
- `applyDraft` throws `CHANGED` when they differ (checked after the idempotency-marker lookup, so a retry of an approval that already landed still gets the stored result).
- `toDTOs` ORs the same check into `targetChanged`, so the card shows the draft as stale.
- DB test: the owner renames the task after drafting; the card flags it, approval fails, and the owner's title stays.

### WR-05: `get_file` truncation splits surrogates and caps characters, not bytes

**Files modified:** `src/server/agents/tools/github.ts`, `tests/db/github-tools.test.ts`
**Commit:** 1526e94
**Applied fix:** The strict UTF-8 check still runs on the full buffer. Truncation now cuts the buffer at 16384 bytes and backs off to the start of a code point (skipping `10xxxxxx` continuation bytes), so no character or surrogate pair is split. Tests:
- An emoji straddling the cap is dropped whole.
- 10000 × `é` truncates to exactly 16384 bytes.

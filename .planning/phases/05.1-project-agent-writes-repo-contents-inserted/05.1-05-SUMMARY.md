# Phase 5.1 Plan 05: Agent project writes Summary

`projects.create` and `projects.update` each create one APPROVE approval; on approval `applyDraft` runs everything in one transaction (project, milestones, mapped tasks, repo/url links, task dependencies) and writes an `audit_log` marker (`project.agent_create|update`, target = approvalId) that makes a retried ambiguous execution return the stored result. Every `{ok:false}` from the server functions is thrown as a ToolError so the whole transaction rolls back. Update merges onto current rows (workspace, notes, reminders, context kept), refuses stale targets (`updatedAt` vs `before`), and verifies every milestone/task id belongs to the project (at call time and again at execute). Sources are built server-side from this run's done list_tree/get_file calls (300-char items, cap 50).

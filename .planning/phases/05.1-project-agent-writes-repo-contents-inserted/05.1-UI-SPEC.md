4. **Facts** grid:
   - `WHAT WILL HAPPEN`: create → `Creates project "{name}" with {m} milestones, {t} tasks and {l} links in LifeOS.` (omit zero clauses; all zero → `Creates project "{name}" in LifeOS.`); add ` Adds {d} task dependencies.` when d > 0. Update → `Changes project "{name}": {k} field changes, {t} tasks, {m} milestones, {l} links.` (only non-zero clauses).
   - `WHERE`: `LifeOS only`.
   - `WHEN`: `Immediately after approval` (existing wording).
5. **WHAT GETS SAVED** section (replaces "WHAT DATA WILL BE SENT"; eyebrow `WHAT GETS SAVED`), existing list style:
   - `check_circle` green: `Project details and context notes ({n} characters)`; `{m} milestones, {t} tasks, {l} links` (non-zero only).
   - `shield` cyan: `Nothing is written to GitHub`.
   - `shield` cyan: `All of it is created together, or not at all` (D-10).
6. **PREVIEW / CHANGES** section (eyebrow `PREVIEW` for create, `CHANGES` for update; `EDITED` amber tag when `edited`; right-aligned meta `{t} tasks · {m} milestones`):
   - **Read mode, create** (one inset panel):
     - Project block: name 15/500; meta line 12.5 `text-2`: `{Category} · ` + priority tag + ` · Target {d MMM yyyy}` or `No target date`; description 14 `text-2` (omitted when empty).
     - Context: eyebrow `CONTEXT` `mt-4`, text 14/1.65 `text-2` `whitespace-pre-wrap break-words`, `line-clamp-6` collapsed with `Show full context` / `Show less` cyan text button (`aria-expanded`). Empty → block omitted. Rendered as plain text, never as HTML or Markdown (repo-derived, untrusted).
     - `MILESTONES` (`mt-4`): rows `flag` icon 16 `text-text-3` + title + right meta `Due {d MMM}` or `No due date` + `{n} tasks`.
     - `TASKS` (`mt-4`): grouped by milestone in milestone order, then `No milestone` group last; group label 12.5 `text-3`. Row: `task_alt` icon 16 `text-text-3`, title (truncate, `title` attr full), priority tag if set, due `12.5 text-3` if set, `Blocked by "{task}"` 12.5 `text-3` if it has dependencies.
     - `LINKS` (`mt-4`): repo link row `link` icon + `font-code` `owner/repo` + `Repository` meta; URL link row `link` icon + label + host 12.5 `text-3`. Links are not clickable in the preview **[auto]** (avoid opening untrusted URLs from an unreviewed draft).
     - Project dependencies (update only, if any): `Depends on "{project}"` rows.
   - **Read mode, update**: field diff using existing `Diff` row style (`NAME`, `DESCRIPTION`, `CONTEXT` (shows `{n} → {m} characters` + Disclosure `Show new context`), `CATEGORY`, `PRIORITY`, `TARGET DATE`); then MILESTONES / TASKS / LINKS lists containing only added or changed items, each with `NEW` or `CHANGED` neutral tag; changed rows show `from → to` for title/due/priority in 12.5 `text-3`. No changes in a group → group omitted. Nothing at all → existing `No fields change.` panel.
   - **Edit mode** (pending only, toggled by existing `EDIT` / `DONE` button):
     - Project fields (`gap-4`): `Name` Input (max 80, required), `Description` Textarea rows 3 max 500 `rounded-14`, `Context` Textarea rows 8 max 4000 `rounded-14` with helper `{n} / 4000 characters`, `Category` Select (`CATEGORY_LABEL`), `Priority` segmented P1/P2/P3 (exact ProjectDialog markup), `Target date` `input type="date"` (clearable).
     - `MILESTONES` group: each row `Title` Input (max 120) + `Due` date Input + remove icon button (`close`, `aria-label="Remove milestone {title}"`). Labels: visible `Field` labels on the first row, `sr-only` on following rows **[auto]**.
     - `TASKS` group (flat list, agent order): `Title` Input (max 200), `Due` date, `Priority` Select (`None`, `P1`, `P2`, `P3`), `Milestone` Select (`No milestone` + current non-removed milestone titles), remove icon button (`aria-label="Remove task {title}"`).
     - `LINKS` group: read-only row (as read mode) + remove icon button (`aria-label="Remove link {label}"`). Repo target cannot be changed (D-15).
     - For `project_update`, `projectId` is never shown as editable; existing-item rows can be edited, items that already exist in the project cannot be removed from the card (removing existing things is out of scope) **[auto]**: only proposed new rows get the remove button.
     - **Remove behaviour**: no confirmation. The row collapses in place to a single line 12.5 `text-3`: `"{title}" removed` + ghost xs button `Restore` (`aria-label="Restore {title}"`). Removing a milestone also shows, on that collapsed line, `Its {n} tasks stay, without a milestone.` and their Milestone selects switch to `No milestone`; Restore does **not** re-assign them **[auto]**. Removing a task silently drops dependencies that referenced it; the WHAT WILL HAPPEN count updates live. Focus after remove moves to the Restore button; after restore, to the row's title input.
     - Validation: on `DONE` and on approve, client runs the same zod schema the server re-runs (D-14); errors inline under the field (`Field error`), first invalid input focused, using messages from the Phase 5 schemas (`Give the project a name.`, `Give the milestone a title.`, `Add a title.`). Group-level error (e.g. over 40 tasks, not reachable by UI but server may return it) shows as `InlineError` text above the group.
   - **Edited disclosure** (existing): `View agent's original` → read-mode preview of `a.original`.
7. **Footer** (existing pattern, uppercase buttons): primary `CREATE PROJECT` / `UPDATE PROJECT` (`check` icon, `min-w-[150px] rounded-full`), secondary `EDIT` / `DONE`, destructive `REJECT`, right meta `requested {HH:mm} · expires {stamp}`. `targetChanged` (update only: project changed since drafting) shows existing amber line with copy below and disables approve.
8. **Resolved** (existing `Resolved` component, extended via `projectResolved`, same as `eventResolved`):
   - approved/executing: `schedule` cyan, `Creating the project…` / `Updating the project…`.
   - executed: `check_circle` green, `Project created: {name}. Approved at {HH:mm}.` / `Project updated: {name}. Approved at {HH:mm}.` + outline link button `Open project` → `/projects/{id}` (id from `result.projectId`, validated as uuid before rendering the link, mirroring `eventResolved`).
   - failed: `error` red, `Approved, but it couldn't be saved: {error}. Nothing was created.` / `… Nothing was changed.` + existing `Retry` button.

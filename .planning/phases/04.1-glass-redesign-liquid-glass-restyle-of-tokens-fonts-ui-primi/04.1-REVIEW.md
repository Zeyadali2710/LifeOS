## Summary

I reviewed the Liquid Glass restyle (diff `d8375b1..HEAD`). I focused on the new shell (header, account menu, tab bar, ask bar, system block), the AI panel and dialog layering, the CSS cascade in `globals.css`, and the e2e specs that were rewritten for the new UI.

These areas checked out:
- Removing compact mode (cookie, shortcut, palette command, tests) is complete. No dangling `crumbFor`, `toggleCompact`, `lo_nav` or `--bottombar-h` references remain.
- `glass-gate.sh` passes on `src`.
- Safe-URL gating in `notification-row.tsx` is unchanged.
- Run detail and the AI views add no new HTML sinks.
- Base styles are correctly moved into `@layer base`.
- The `@supports not (backdrop-filter)` fallback covers older Safari now that the `-webkit-` prefix is gone.

The real defects come from the new glass layering:
- `backdrop-filter` makes an element the containing block for its `position: fixed` descendants. This breaks a modal dialog that is rendered inside a glass card.
- The new z-index order puts the docked AI panel above both the header's stacking context and every `Dialog`.
- One rewritten e2e assertion contradicts the component's focus behaviour, so it will fail.

## Critical Issues

### CR-01: Task dialog is trapped inside a `glass-card` (backdrop-filter breaks `position: fixed`)

**File:** `src/organization/tasks-card.tsx:137` and `:223`, root cause in `src/ui/dialog.tsx:41`
**Issue:** `TasksCard`'s `<section>` changed from a plain bordered box to `glass-card`, which sets `backdrop-filter: blur(30px) saturate(160%)`. Under the Filter Effects spec (implemented by Chrome, Safari and Firefox), an element with a non-`none` `backdrop-filter` becomes the containing block for its `fixed` and `absolute` descendants and also forms a stacking context. `<TaskDialog>` is rendered inside that section (line 223), and `Dialog` positions itself with `fixed inset-0 z-50`. As a result:
- The edit-task modal's backdrop and centring are sized to the tasks card, not the viewport.
- The dialog cannot paint above later siblings or the header and tab bar (`z-30`), because its `z-50` is confined to the card's stacking context.
- The `sheet` variant is pinned to the bottom of the card on mobile.

It only looks right when blur is disabled (reduced transparency or increased contrast), so a quick visual check in a default browser does not catch it. Any future `Dialog` placed inside a `glass-card`, `glass-panel` or `glass-chrome` element will hit the same problem.
**Fix:** Fix it once in the shared primitive by portalling every dialog to `document.body`, the same way `snooze-menu.tsx` already does:
```tsx
// src/ui/dialog.tsx
import { createPortal } from "react-dom";
...
  if (!open) return null;
  return createPortal(
    <div className={`fixed inset-0 z-50 grid bg-black/40 ...`} ...>
      ...
    </div>,
    document.body,
  );
```

### CR-02: Docked AI panel (z-60) covers the account menu, header tooltips and every modal Dialog

**File:** `src/shell/ai-panel.tsx:150`, `src/shell/header.tsx:31`, `src/shell/account-menu.tsx:97`, `src/ui/dialog.tsx:41`
**Issue:** In `docked` mode (viewport of 1100px or wider) the panel is returned without a wrapper as `absolute top-[80px] right-3 bottom-3 z-[60]` in the root stacking context. It used to be an unstacked flex child. The fixed header is `z-30`, so the account menu (`z-40`) and the nav tooltips (`z-50`) can never paint above `z-30` at root level. The account menu opens at about y=73px, right-aligned at the avatar, which is exactly where the docked panel sits (from y=80px, right 12px, 440px wide). While the assistant is open:
- The account menu (Knowledge, Goals, Settings, Sign out) renders underneath the panel. Pointer users cannot reach it: a click lands on the panel and the outside-click handler closes the menu. Keyboard users move focus through items they cannot see.
- `Dialog` is `z-50`, which is below the panel's `z-60`. On 1100–1500px viewports a centred 420–520px dialog overlaps the panel's column. This affects event, task, scope, remove-token and disconnect dialogs. Part of the modal, including the right-aligned action buttons, is hidden under a non-modal panel that stays clickable while the dialog claims `aria-modal`.
**Fix:** Give docked mode a z-index below the header and below dialogs, and lift the header above it. The modal overlays (palette, drawer, More sheet at 70) stay above both:
```tsx
// ai-panel.tsx: z only on the docked aside; overlay/sheet keep the z-[60] wrapper
className={`glass-panel absolute top-[80px] right-3 bottom-3 ${mode === "docked" ? "z-[25]" : "z-[60]"} flex ...`}
// header.tsx
<header className="pointer-events-none fixed inset-x-4 top-[14px] z-[45] ...">
```

### CR-03: shell-nav e2e asserts the wrong focused menu item, so it will fail

**File:** `tests/e2e/shell-nav.spec.ts:66-70`
**Issue:** The test focuses the avatar, presses Enter, then ArrowDown, and expects `menuitem.first()` to have focus. But `AccountMenu`'s open effect already focuses `items()[Math.max(currentIdx, 0)]` (`account-menu.tsx:30`). On `/career`, `currentIdx` is -1, so Knowledge (the first item) gets focus as the menu opens. ArrowDown then calls `go(i + 1)` and moves focus to Goals, so the `toBeFocused()` assertion on the first item fails.
**Fix:** Assert the item focused on open, then the arrow movement:
```ts
await page.keyboard.press("Enter");
await expect(page.getByRole("menuitem").first()).toBeFocused();
await page.keyboard.press("ArrowDown");
await expect(page.getByRole("menuitem").nth(1)).toBeFocused();
```

## Warnings

### WR-01: "Docked" AI panel no longer reserves space and hides page content

**File:** `src/shell/ai-panel.tsx:150,287`, `src/shell/app-shell.tsx:41`
**Issue:** Before this phase, docked mode was a `shrink-0` flex sibling, so `main` reflowed. Now `main` is `absolute inset-0` and the panel floats over its right ~452px with no backdrop and no reflow. On 1100–1400px viewports this hides the approvals detail column, the organization plan and tasks column, and right-aligned page actions until the assistant is closed. The panel is still non-modal, so the hidden content stays in the tab order but cannot be seen.
**Fix:** When `aiOpen && mode === "docked"`, add matching right padding to the content wrapper (for example `desk:pr-[464px]` via a shell flag). Alternatively, treat 1100px+ as `overlay` mode with the backdrop.

### WR-02: Menu focus indicator is invisible on the current item and indistinguishable from hover

**File:** `src/shell/account-menu.tsx:65,113`, `src/shell/snooze-menu.tsx:64`
**Issue:** Menu items use `focus-visible:outline-none focus-visible:bg-white/[.10]` (snooze uses `focus:`). That is the same treatment as hover, and a 10% white fill on `rgba(38,38,42,.94)` is well under the 3:1 non-text contrast required by WCAG 1.4.11 / 2.4.7. On the current page's item (`bg-white/[.12]`), focus changes .12 to .10, which is effectively invisible. That item is also the one the menu focuses on open.
**Fix:** Keep the global cyan ring. Drop `outline-none` and add an inset outline:
```
focus-visible:outline-2 focus-visible:-outline-offset-2 focus-visible:outline-cyan
```

### WR-03: `text-text-3` used inside a chrome pill, which the project's own contrast test bans

**File:** `src/shell/header.tsx:98`
**Issue:** The search shortcut hint (`Ctrl K` / `⌘K`) is `text-text-3` inside the `glass-chrome` pill. `tests/unit/contrast.test.ts:52-55` asserts that text-3 is below 4.5:1 on the worst-case chrome backdrop ("banned inside pills").
**Fix:** Use `text-soft`.

### WR-04: Informational meta text uses the "decorative only" text-4 token

**File:** `src/ui/section-header.tsx:9`
**Issue:** `meta` holds real information ("3 WAITING", "LAST 24 HOURS", the tool-call count in `run-detail.tsx:143`). It now renders in `text-text-4` (#636366), which `globals.css:15` marks as decorative only. At 10.5px on the `#202022` card that is about 2.7:1, which fails WCAG 1.4.3.
**Fix:** `text-text-3`.

### WR-05: `--font-mono` now points to a proportional font

**File:** `src/app/globals.css:164`; affected: `src/settings/token-form.tsx:76`, `src/settings/icloud-form.tsx:58`, `src/settings/spend-section.tsx:82,91`, `src/agents/run-detail.tsx:52,153`, `src/ui/badge.tsx:16`
**Issue:** `--font-mono: var(--font-grotesk), ...` silently turns every remaining `font-mono` into Familjen Grotesk. Two effects:
- The secret-entry inputs (GitHub token, iCloud app-specific password) lose glyph disambiguation (l/I/1, 0/O), which matters when checking pasted secrets.
- The spend table's numeric columns stop lining up.

The phase introduced `font-code` for code blocks but left these call sites, so the utility name now lies.
**Fix:** Switch the secret inputs to `font-code`, add `tabular-nums` to numeric cells, and either restore a real monospace stack for `--font-mono` or rename the remaining uses.

### WR-06: Mobile "New event" FAB overlaps the new tab bar

**File:** `src/organization/header.tsx:137`
**Issue:** The FAB is `max-tab:fixed bottom-[calc(76px+safe-area)] z-30`. The new tab bar sits at `bottom: 14px + safe-area` and is 68px tall (`p-1.5` + `h-14`), so its top edge is 82px up. The FAB's bottom 6px sits under the tab bar. Both are `z-30` and the tab bar comes later in the DOM, so the tab bar paints over the FAB.
**Fix:** `max-tab:bottom-[calc(96px+env(safe-area-inset-bottom))]`. Better, derive it from the unused `--tabbar-h` token.

### WR-07: Header primary nav targets are 40px on touch tablets

**File:** `src/shell/header.tsx:63`
**Issue:** The nav links are `h-10 min-w-10` with no `[@media(pointer:coarse)]` override, unlike `ctl` and the search button. The nav shows from 760px, so on iPad-class touch devices the primary navigation is below the 44px minimum the a11y spec enforces elsewhere. The mobile a11y e2e only checks below 760px, so it does not catch this.
**Fix:** Add `[@media(pointer:coarse)]:h-11 [@media(pointer:coarse)]:min-w-11`.

### WR-08: "Today's plan" became a nested complementary landmark

**File:** `src/organization/plan-card.tsx:175,240`
**Issue:** The `<section aria-label>` became `<aside aria-label>`. It is rendered inside `organization-view.tsx:353`'s own `<aside>`, which sits inside `<main>`. That gives a complementary landmark nested in another complementary landmark inside main, which axe flags (`landmark-complementary-is-top-level`). It also changes the role from region to complementary, which any role-based locator for this card would no longer match.
**Fix:** Revert to `<section aria-label="Today's plan">`.

### WR-09: Shell status is fetched by five independent hook instances that can disagree

**File:** `src/shell/header.tsx:24-25`, `src/shell/tab-bar.tsx:40-41`, `src/shell/account-menu.tsx:16`, `src/shell/system-block.tsx:10,39`
**Issue:** `useSystemState()` calls `useAgentStatus()` internally, and `Header` and `TabBar` also call `useAgentStatus()` directly. Each instance keeps its own state and fires its own `/api/agents/status` fetch on mount and on every run or approval frame. The approvals badge, the `RUNNING` count and the attention dot each come from a different fetch that resolves at a different time, so they can briefly disagree. A 401 also triggers several `location.assign` calls.
**Fix:** Have `useSystemState` return `status` and use that single result in `Header` and `TabBar`. Better, hold the agent status once in `LiveProvider` or `ShellProvider` context.

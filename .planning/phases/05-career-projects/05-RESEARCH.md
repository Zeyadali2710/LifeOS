The biggest risks are data-coverage honesty, not technology. ### Schema (recommended; names follow docs/database.md)

All ids `uuid().primaryKey().defaultRandom()`, `...timestamps`, dates as Sydney `"YYYY-MM-DD"` text exactly like `tasks.dueDate` (lexicographic comparison works; reuse `sydneyYmd`/`addDaysYmd` from `src/server/calendar/free-slots.ts`).

- `projects`: `name text not null`, `description text not null default ''`, `category text not null`, `status text not null default 'active'`, `priority int not null default 2`, `targetDate text`, `workspacePath text`, `workspaceMachine text`, `blockerNote text not null default ''`. Index on `(status, priority)`. CHECK constraints for category/status/priority are cheap and make bad rows impossible; Zod still validates first.
- `milestones`: `projectId uuid not null -> projects ON DELETE CASCADE`, `title`, `dueDate text`, `completedAt tstz`, `sortOrder int not null default 0`; index `(projectId, sortOrder)`.
- `tasks`: add `milestoneId uuid -> milestones ON DELETE SET NULL`; add FK on existing `projectId -> projects ON DELETE SET NULL` (D-06). Existing rows have null `project_id` (never written before Phase 5), so the FK add cannot fail. Index `tasks(project_id)` and `tasks(milestone_id)`.
- `task_dependencies`: `taskId`, `blockedByTaskId` both `-> tasks ON DELETE CASCADE`, composite PK, `CHECK (task_id <> blocked_by_task_id)`, index on `blocked_by_task_id`.
- `project_dependencies`: same shape on projects (CONTEXT lists only `task_dependencies`; project to project "blocked by" in D-08 needs its own table - recommend this name).
- `project_links`: `projectId -> projects CASCADE`, `kind text` ('repo'|'url'), `repoId bigint -> github_repos ON DELETE CASCADE` (null for url), `url text`, `label text`; `CHECK ((kind='repo' AND repo_id IS NOT NULL AND url IS NULL) OR (kind='url' AND url IS NOT NULL AND repo_id IS NULL))`; partial unique index `(project_id, repo_id) WHERE repo_id IS NOT NULL`. A repo may be in many projects (D-11) so no unique on repo_id alone. URL validation: zod `.url()` plus `^https?://` refinement; render as `rel="noopener noreferrer"`; see `src/lib/safe-url.ts` for the existing GitHub URL helper pattern.
- `github_repos.languages jsonb` typed `Record<string, number> | null` (null = never fetched, `{}` = fetched, no languages).

FK choices rationale: project delete must not delete tasks (tasks belong to the whole OS) so SET NULL; milestone delete likewise; dependency/link rows are edges so CASCADE. D-05 "delete only after unlinking" is enforced in the server function (count of tasks/milestones/links; confirm dialog) - the FK alone would silently orphan tasks.

### Pattern 1: Cycle detection (recursive CTE)
Adding edge "A blocked by B" creates a cycle iff A is already reachable from B following "blocked by" edges (or A = B).

```sql
-- $1 = A (taskId), $2 = B (blockedByTaskId)
WITH RECURSIVE reach(id) AS (
  SELECT blocked_by_task_id FROM task_dependencies WHERE task_id = $2
  UNION                                   -- UNION (not ALL) dedups, so it terminates even on pre-existing cycles
  SELECT d.blocked_by_task_id FROM task_dependencies d JOIN reach r ON d.task_id = r.id
)
SELECT 1 FROM reach WHERE id = $1 LIMIT 1;
```
Run in one `h.transaction`, first `select pg_advisory_xact_lock(hashtext('task_deps'))` (project: `'project_deps'`) so two concurrent inserts cannot jointly create a cycle (single owner makes this rare but the lock is one line). Return `{ok:false, errors:{blockedBy:"This would create a circular dependency."}}`. Use drizzle `sql` template with parameters (never string-concat ids). [CITED: postgresql.org/docs/17/queries-with.html - recursive CTE, UNION dedup for cycle safety]

### Pattern 3: Languages in the sync (D-04)
GitHub: `GET /repos/{owner}/{repo}/languages` returns a flat object `{ "TypeScript": 123456, "CSS": 7890 }`, values are bytes of code per language; only 200 documented. [CITED: docs.github.com/en/rest/repos/repos#list-repository-languages]

Fit into `createSync`: inside the `for (const r of active)` loop add
```ts
const langRes = await cond(`${base}/languages`, z.record(z.string(), z.number().int().nonnegative()));
if (langRes) {
  await h.update(githubRepos).set({ languages: langRes.data }).where(eq(githubRepos.id, r.id));
  await langRes.save();
}
```
- Existing `cond()` handles ETag + 304; save-after-persist ordering is already the pattern. First sync after deploy has no ETag row so every active repo gets a 200 and is backfilled automatically. Empty repos return `{}` - store `{}`.
- Budget: currently per active repo = 1 (pulls) + N open-PR review calls + 1 issues + 1 commits + 1 runs; plus `/user` and `/user/repos` once. Adding 1 call x <=30 repos is about +20% of the base; 304s are cheap. Authenticated REST limit is 5,000 req/h [ASSUMED: from training; the docs page fetched did not cover rate limits] and conditional 304s do not count against the primary limit [ASSUMED]. The sync already maps rate-limit errors to `{error:"rate_limit"}` + retry; no change needed.
- Use `z.record(...)` so unknown languages parse; GitHub may return 404/451 for unavailable repos - `GithubError("not_found")` currently aborts the whole sync via the outer catch. Wrap just the languages call in try/catch for `not_found` (skip), re-throw others, so a stale repo cannot stall the sync.
- Testing: `tests/helpers/fake-github.ts` routes `"GET /repos/o/r/languages"`; extend `tests/db/github-sync.test.ts` (languages stored; 304 on second run leaves value; `{}`; not_found does not abort).
- Language bar (pure): sort desc by bytes, top 5 + "Other", percentage = bytes/total; fall back to `github_repos.language` single-colour bar when `languages` is null. Language colours: a tiny fixed map of ~10 languages plus a neutral for others (do not fetch GitHub's linguist colours).

### Pattern 4: Pure rules module (D-09, D-10) - `src/lib/project-rules.ts`
Inputs are plain DTOs plus `today: string` (Sydney ymd) so there is no clock access inside.

- `progress({tasks, milestones})`: `tasks.length>0 ? done/total : milestones.length>0 ? msDone/msTotal : null` (`null` renders "no tasks yet"). Return `{pct, basis:'tasks'|'milestones'|'none'}`. Done/archived tasks count as is; tasks with `completedAt` set are done.
- `ciHealth(runs, defaultBranch)`: filter runs to `branch === defaultBranch`, sort by `ghCreatedAt` desc, ignore `status !== 'completed'` (queued/in_progress) and conclusions `cancelled|skipped|neutral|stale`; first remaining: `success` -> `passing`; `failure|timed_out|startup_failure|action_required` -> `failing`; nothing -> `none`.
- `overdue`: open task overdue when `dueDate < today` (date-only, Sydney) or `dueAt < now` when a time is set - simplest consistent rule: reuse `dueAt` (already derived: date-only means 23:59 Sydney) and compare to `now`, so no new time logic. Milestone overdue: `!completedAt && dueDate < today`.
- `health(project, {overdueCount, progressPct, ciFailing, today})` returns `'behind' | 'at_risk' | 'on_track' | null` (null when status is not Active, so Paused/Done/Archived show only owner status). Rules in order: Behind if any open task or open milestone overdue (also recommended: target date passed and not Done - flagged A2); At risk if (target within 0-7 days and progress < 80) OR any linked repo's `ciHealth === 'failing'`; else On track.
- `blockers(...)` returns a typed list `{kind:'task_blocked'|'project_blocked'|'milestone_overdue'|'ci_failing', ref, label}`: open tasks having at least one `blockedBy` task with `completedAt == null`; project dependencies whose blocking project `status !== 'done'` (archived blocker still blocks? recommend: treat archived as not blocking - A3); overdue milestones; linked repos with failing CI. Blocker note is returned separately, not derived.
- `sparkline(commits, now, days=14)`: 14 daily buckets in Sydney days (via `sydneyYmd`) -> number[]; render as inline SVG.
- `buildBrief(project...)` Markdown string: title, description, status/priority/target, open tasks (with due), blockers, milestones, linked repos + CI. Pure so it is snapshot-testable; cap lengths. `launchCommand(path)`: `cd "<path>" && claude` - reject paths containing `"`, backtick, `$`, `\n`, or `\r` in the zod payload (the string is copied into the owner's shell; D-14 forbids protocol launching, and the copy-only design is the mitigation) and for Windows paths accept `C:\...` as-is.

Computation location: query modules load a project's tasks, milestones, dependency rows and linked repos' latest runs in ~5 bounded queries and hand them to the pure functions. Do not build SQL aggregates for health (duplicates rules; untestable without VM). Owner-scale data (tens of projects, hundreds of tasks) makes this safe.

## Common Pitfalls

### P1: Sync data coverage is partial
**What:** Issues stored only if owner authored/assigned; commits newest 20 on default branch; 5 runs; child data only for non-archived repos pushed within 90 days (max 30); `/user/repos` first page only (100).
**Avoid:** label "Your open issues"; raise commits to `per_page=100` (URL change just invalidates one ETag; commits insert is `onConflictDoNothing`); show "Not synced" for repos outside the active window rather than 0; test fixtures covering archived/stale repos.

### P2: Open PR/issue counts go stale on closed items
Counts must be `state='open'` filtered at query time, not row counts. Merged PRs have `state='closed'`.

### P3: Invalid uuid / owner/repo params
`/projects/not-a-uuid` makes Postgres throw (500). Validate with zod before querying; return `notFound()`.

### P4: Languages 404 aborts the entire sync
`cond()` throws `GithubError('not_found')` caught by the outer catch (whole sync reports `other`). Wrap languages call per repo (see Pattern 3).

### P5: FK + migration ordering
drizzle-kit generate emits `ALTER TABLE tasks ADD CONSTRAINT ... FOREIGN KEY (project_id)` - confirm `projects` is created before it in the SQL; keep one migration. Verify `tests/db/migrations.test.ts` and add `tests/db/schema-projects.test.ts`. After changing the Drizzle schema also commit `drizzle/meta` snapshot and journal.

### P6: Timezone drift
Use Sydney ymd strings for milestone/target dates; compare against `sydneyYmd(now)`, never `toISOString().slice(0,10)` (UTC).

### P7: Project delete vs data
SET NULL FKs hide orphaning; enforce the "no linked data" rule in `deleteProject` and test it.

### P8: Health flapping from running CI
Ignore in-progress/cancelled runs in `ciHealth` (a run in progress must not flip passing to none).

### P9: Server Actions in Next 16
Each action file needs `"use server"` and must re-check `requireOwner()` inside every exported action (see `task-actions.ts`); do not export non-async helpers from a `"use server"` file (put them in the non-action module).

### P10: Client-safe boundary
`project-rules.ts`, `project-payload.ts`, `project-types.ts` must not import from `src/server/*` (client dialogs import payload schemas; `task-payload.ts` has the "Client-safe" comment convention).

## Code Examples

Pure rule skeleton (client-safe):
```ts
export type Health = "on_track" | "at_risk" | "behind";
export function computeHealth(i: { status: string; targetDate: string | null; today: string; progressPct: number | null; overdue: number; ciFailing: boolean }): Health | null {
  if (i.status !== "active") return null;
  if (i.overdue > 0) return "behind";
  const soon = i.targetDate !== null && i.targetDate >= i.today && i.targetDate <= addDays(i.today, 7);
  if ((soon && (i.progressPct ?? 0) < 80) || i.ciFailing) return "at_risk";
  return "on_track";
}
```

## Security Domain

### Applicable ASVS Categories (level 1)
| Category | Applies | Control |
|----------|---------|---------|
| V2/V3 Auth/Session | yes (existing) | `requireOwner()` at the top of every page and server action |
| V4 Access Control | yes | Single owner; agent tools READ tier only; no write tools |
| V5 Input Validation | yes | zod payloads (name/desc length caps, enum categories, `YYYY-MM-DD`, uuid ids, http(s) URL, workspace path charset) |
| V6 Cryptography | no | none new |
| V12/V13 (output, API) | yes | React escaping; no `dangerouslySetInnerHTML` for descriptions/briefs; links `rel="noopener noreferrer"`, GitHub links through the `isSafeGithubUrl` pattern |

### Threat Patterns
| Pattern | STRIDE | Mitigation |
|---------|--------|------------|
| `javascript:`/`data:` URL in project links | Tampering/XSS | zod `^https?://` refine; render only validated URLs |
| Shell injection via copied launch command | Tampering | Reject `"`, backtick, `$`, newline in path; copy-only (no execution); D-14 forbids protocol handlers |
| SQL injection in palette/project search | Tampering | Drizzle parameterised `ilike` with escaped wildcards; CTE via `sql` template params |
| Race creating dependency cycle | Integrity | Advisory lock + CTE in one transaction |
| Unbounded agent tool output / prompt injection via project text | Info disclosure | Truncate strings (`cut`), cap lists, omit `workspacePath`; treat description/notes as data |
| Error leakage | Info disclosure | `run()` wrapper logs errors without contents (`log.error({err})`), returns generic `failed` |
| IDOR on `/projects/[id]` | Access | Owner-only app; uuid validated; no multi-tenant data |

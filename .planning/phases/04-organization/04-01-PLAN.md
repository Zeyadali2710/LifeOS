<threat_model>
## Trust Boundaries
| Boundary | Description |
|----------|-------------|
| agent -> approval payload | model-produced payload (possibly steered by prompt injection in event text) enters the approval row |
| owner browser -> decide/saveEdit | edited payload from the client is untrusted until re-validated |

## STRIDE Threat Register
| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | decide/saveEdit edited payload | mitigate | server re-parses with payloadSchemaFor(tool) and checkLocked rejects changes to calendarId/eventId/etag/scope/instanceStart/before; payloadHash stays on the original |
| T-04-02 | Elevation of privilege | edit-before-approve retargeting another calendar or event | mitigate | LOCKED fields per kind; delete payload has no editable fields |
| T-04-03 | Information disclosure | ProviderError text in approvals.error / UI | mitigate | ProviderError message is a fixed caller-chosen string, never a raw provider body or token |
| T-04-04 | Repudiation | approval edits | mitigate | aud("approval.edit", {original, edited}) kept for every kind |
</threat_model>

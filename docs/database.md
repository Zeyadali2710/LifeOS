# Database

Postgres 17 + pgvector. Schema in `src/server/db/schema.ts` (Drizzle), migrations in `drizzle/` generated by `drizzle-kit generate` and applied by `npm run db:migrate`. Never `drizzle-kit push` against a real database.

## Conventions
- `id uuid primary key default gen_random_uuid()` (text ids for Better Auth tables, which it generates).
- `created_at`/`updated_at timestamptz` everywhere.
- Enums as Postgres enums for small closed sets (status, tier, category).
- JSONB only for: raw provider payloads, tool inputs/outputs, automation definitions, activity event payloads.
- Synced entities: unique `(provider, external_id)`.
- Single-user, but rows carry `user_id` where ownership matters so authorization checks stay explicit.

## Phase 1 tables
| Table | Purpose |
|---|---|
| `user`, `session`, `account`, `verification` | Better Auth (owner login, sessions) |
| `audit_log` | Security-relevant actions (actor, action, target, ip, metadata) |
| `settings` | Key/value owner settings |
| `activity_events` | Append-only global event stream; index `(occurred_at desc)`, `(type)` |
| `notifications` | Category, priority, source, entity link, read/snooze/dismiss; partial index on unread |

## Phase 4 tables (migration `0003_organization.sql`)
| Table | Purpose |
|---|---|
| `calendars` | One row per synced calendar, FK to the connection (`integrations`) |
| `calendar_events` | One row per Google event/override or per CalDAV resource (raw ICS kept for CalDAV). Recurring instances are expanded at read time, not stored |
| `tasks` | Owner tasks; `project_id` FK (ON DELETE SET NULL) and `milestone_id` link them to Phase 5 projects and milestones |

Deletes cascade connections -> calendars -> calendar_events. Calendar secrets live encrypted in `integrations` (no `last4` kept).

## Phase 5 tables (migration `0005`)
| Table | Purpose |
|---|---|
| `projects` | Owner projects (category, status, priority, target date, workspace path/machine, blocker note, archived) |
| `project_links` | Links a project to a synced GitHub repo or an external URL; unique per project and repo |
| `milestones` | Per-project milestones with optional due date and completion |
| `task_dependencies` | Task blocked-by-task edges; cycles rejected |
| `project_dependencies` | Project depends-on-project edges; cycles rejected |

Also: `github_repos.languages` (jsonb byte counts, null = never fetched); `tasks.project_id` FK is ON DELETE SET NULL; `tasks.milestone_id` references `milestones`.

## Phase 5.1 (migration `0007_project_context`)
`projects.context` (text, default empty): plain-text context notes shown in the workspace card and included in Copy context (`## Context`). Audit markers `project.agent_create` / `project.agent_update` carry the approval id (D-11).
